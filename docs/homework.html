ДЗ 1 — Taskboard: пустая строка и неверный счётчик

Время: 90 минут. Сдаётся: ссылкой на ваш клон этого репозитория с выполненной работой (или архивом папки).

Раздатка (PDF) Слайды лекции (PDF) Стартер Изменение требования Интерактивная модель цикла

Что дано

  • src/tasks.ts — логика доски, src/App.tsx — экран, src/tasks.test.ts — два теста, которые проходят.
  • ISSUE-7.md — отчёт пользователя.
  • AGENTS.md — команды запуска и правила для агента.

Подготовка (5 минут)

Нужен Node.js 20+. Стартер — в публичном репозитории: склонируйте его (git clone https://github.com/olonho/agentic-class) или скачайте папку homework/start архивом.

npm install    # зависимости
npm test       # два стартовых теста, оба зелёные
npm run dev    # dev-сервер; URL печатает Vite, обычно http://localhost:5173

npm run build — проверка типов (tsc --noEmit) и production-сборка. Подробности и правила для агента — в AGENTS.md.

Требования (обязательны все)

R1. По issue #7: переименование в строку из одних пробельных символов отклоняется, остаётся прежнее название; пробелы по краям обрезаются. Пробельные: пробел, табуляция, неразрывный пробел U+00A0.
R2. Доска не показывает пустые строки — включая строки, сохранённые до исправления (в данных такая уже есть).
R3. Счётчик «Открытых» считает так же, как список: пустая строка не считается открытой задачей.
R4. На каждое из R1–R3 — тест. Тесты пишете вы, до того как покажете задачу агенту.

Требования R2–R3 в issue не упомянуты: их нужно найти самому, проверив весь экран, а не только отчёт.

Ход работы

  1. SPEC.md — без ИИ (15 мин). Разделы: Requirement · Acceptance tests (по одному на R1–R3; R4 — это сами тесты) · Non-goals · Files in scope · Definition of done.
  2. Тесты первыми (20 мин). В src/tasks.test.ts или отдельном файле. Агент их не увидит.
  3. Агент (20 мин). Дайте ему только SPEC.md и промпт:
    Прочитай SPEC.md и реализуй задачу точно по нему. Меняй только src/tasks.ts и src/App.tsx. После изменений запусти npm test и покажи результат.
    Код не правите. Каждое вмешательство — строка в INTERVENTIONS.md (время · что · зачем).
  4. Проверка (10 мин). mkdir -p evidence; npm test; npm run build; npm run dev и скриншот в evidence/app.png; git diff --stat.
  5. Красный прогон (10 мин). По очереди сломайте три места и на каждое покажите красный тест:
    • (а) обрезание пробелов при создании в createTask;
    • (б) валидацию при переименовании в renameTask;
    • (в) обработку унаследованной пустой строки (R2).
    Каждую поломку — отдельным блоком в evidence/red.txt с меткой (а), (б), (в). Лог удобно собирать так: npm test 2>&1 | tee -a evidence/red.txt, подписывая блок.
  6. REPORT.md (10 мин). На каждый провал — строка <категория>: <что произошло> → <правило> с уликой (строка транскрипта, хунк диффа или имя теста). Правило — тест, правило линтера или строка AGENTS.md; оно должно ловить вариант того же провала, а не только тот случай, который вы уже видели.
  7. REFLECTION.md (5 мин, без ИИ). Пять строк: что агент понял не так и какая строка спеки это вызвала; какой ваш сигнал оказался ложным и что вы им заменили; какое правило вы добавили и какой провал оно закрывает.

Изменение требования (после шага 5)

После того как шаг 5 сдан, требование меняется: название из одного символа U+200B (zero-width space) тоже считается пустым. Обновите SPEC.md, тесты и реализацию тем же циклом (спека → агент → проверка → красный прогон на новом варианте).

Оценка — 6 баллов

БаллЗа что
1SPEC.md — пять разделов, написан без ИИ
1тесты на R1–R4 в репозитории, зелёные
1evidence/app.png + evidence/red.txt с тремя блоками (а), (б), (в)
1INTERVENTIONS.md — все вмешательства
1REPORT.md — таксономия с уликами + правило, ловящее вариант
1REFLECTION.md — пять строк
Скрытый набор тестов преподавателя — обязательный гейт: если он не проходит, работа не зачтена. Команду запуска и сами тесты преподаватель не выдаёт.
Защита, 3 минуты: по команде преподавателя сломать одно из трёх мест в вашей реализации и показать, что краснеет; объяснить, почему зелёный значит «проверено».

Не зачтено

  • SPEC.md писал ИИ; тесты писал агент.
  • В red.txt нет одной из трёх поломок, или после поломки тесты остались зелёными.
  • Правило не ловит вариант провала.
